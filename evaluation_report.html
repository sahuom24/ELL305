× Hard Truths & Justification for Deducted Marks (−7 Marks)
  • Synthetic Procedural Model vs. Real Binary Traces (−3 Marks): Workload B is an algorithmically synthesized C# model, not an authentic execution trace dumped from compiled SPEC CPU binaries using Intel PIN or gem5. Real binaries have irregular indirect jumps (`JALR`) and OS context switches.
  • Bitcells vs. Physical SRAM Macro Overheads (−2 Marks): The cost model assumes ideal storage bits, ignoring peripheral SRAM decoders, sense amplifiers ($40\%–80\%$ silicon area expansion), and multi-ported wiring congestion.
  • Chooser Adaptation Latency (−1 Mark): Omission of chooser hysteresis analysis; when a branch changes phase, 2-bit counters take multiple contrary outcomes to invert, causing transient misprediction spikes.
  • Checkpoint Stack Invalidation Logic (−1 Mark): Checkpoints are modeled as static registers, omitting the circular FIFO allocation and flash-invalidation logic needed on branch flushes.

3 Technical Analysis of Key Sections

Section 2 & 3: CPI Sensitivity & Speculative Checkpointing
The quantitative demonstration that halving mispredictions from $10\%$ to $5\%$ boosts IPC by $22\%$ on a 14-cycle pipeline provides immediate physical motivation. Incorporating Equation (7) ($S_{\text{chk}} = N_{\text{chk}} \cdot [h_{\text{GHR}} + \lceil\log_2 B\rceil]$) accounts for the fact that out-of-order processors must update the GHR at Fetch to avoid predicting subsequent branches with stale history. Figure 2 correctly details single-cycle rollback from Chk[1].

Section 4: Classical Lineage & The 9-Variant Taxonomy
The mathematical analysis of Smith's 2-bit counter proves why two consecutive contrary outcomes are required to flip state, halving loop-exit penalties. The systematic classification of $GAg$ to $SAp$ in Figure 4 and Section 4.2.1 is authoritative. Section 4.2.2 proves that $PAp$ demands 33.6 Megabits of SRAM for 4,096 branches, explaining why commercial chips embraced $PAg$ and $gshare$.

4 Viva Voce / Defense Examination: 5 Trap Questions

The student authors must be prepared to defend the following microarchitectural questions during the oral defense:

Question 1: The 704-Bit Checkpoint Calculation (Equation 8)
Question: In Equation (8), you multiply $32 \times (12 + 10) = 704\text{ bits}$. What physical registers do the 12 and 10 represent?
Model Answer: 12 bits is the width of the Global History Register (GHR). But because the Local Predictor also updates speculatively, we must checkpoint which local entry was accessed ($\log_2(1024) = 10\text{ bits}$) and its pre-speculative pattern. Thus, each of the 32 in-flight branch frames requires $12 + 10 = 22\text{ bits}$, totaling 704 flip-flops.
Question 2: Why Did PAg Collapse to 85.21% in Workload B?
Question: In Table 4, PAg achieves 94.06% accuracy, but in Table 5 it collapses to 85.21%. Why does procedural code cause local history to fail?
Model Answer: In procedural code, control flow crosses function boundaries. A branch inside a helper function depends on execution decisions made in the caller routine. Because PAg records only the local branch PC's own history, it is blind to caller context. Gshare and GAg win in procedural code because their global history threads across call boundaries.
Question 3: Why Bitwise XOR in Gshare?
Question: Why did McFarling choose bitwise XOR rather than addition or concatenation?
Model Answer: XOR is a bijective, information-preserving hash: $A \oplus B = C \iff C \oplus B = A$. It preserves 100% of input entropy with zero carry propagation delay. Concatenation wastes table rows when fields share redundant bits, while addition adds carry-chain gate latency. XOR scrambles accesses uniformly across the PHT with zero added SRAM bits.
Question 4: Why 3-Bit Counters in Local PHT vs. 2-Bit in Global?
Question: In Figure 5, the Alpha 21264 uses 3-bit counters for local prediction, but 2-bit for global. Why?
Model Answer: The local table predicts loops. In nested loops with occasional anomalous exits, 2-bit counters sit in weakly taken states and flip easily. 3-bit counters provide 8 states with a threshold at 4, providing deeper hysteresis that requires 3 consecutive contrary outcomes to flip, stabilizing loop predictions at an extra cost of only 1 bit per entry.
Question 5: Critical Path Latency & Decoupled Pipelining
Question: Why can't the Alpha 21264 local predictor deliver its prediction in 1 cycle at 1 GHz?
Model Answer: The local predictor requires two dependent memory accesses: $PC \rightarrow \text{LHT} \rightarrow \text{LPT}$. In sub-nanosecond cycle times, two sequential SRAM reads cannot complete in 1 cycle. Modern cores decouple the front-end: a single-cycle $\mu\text{BTB}$ provides branch targets in Cycle 1 with zero bubbles, while the 2-cycle tournament engine validates and overrides in Cycle 2.
